OpenArm 双臂托盘举升任务代码使用文档

文档说明
本文档面向当前仓库中的双臂托盘举升任务 Isaac-Lift-Tray-OpenArm-Bi-v0，说明实际运行环境、Docker 部署方法、训练与评估命令、关键模块作用、核心参数含义以及常见问题处理方式。本文档已经按照当前代码和现有日志进行整理，运行方式统一为 Docker。

---

零、快速上手

本节给出从零开始到完成训练、回放、查看曲线的最短操作路径，适合已有 Docker 和 NVIDIA 驱动环境的用户直接对照执行。

0.1 环境配置

第一步：拉取镜像（宿主机执行）。

```bash
docker pull nvcr.io/nvidia/isaac-lab:2.3.0
```

第二步：允许容器访问显示服务，并启动容器（宿主机执行）。将 /home/jintao/isaac_ws 替换为你的工作区路径，缓存目录可按需调整。

```bash
xhost +
docker run --name isaac-lab --entrypoint bash -it --gpus all --rm \
  -e "ACCEPT_EULA=Y" -e "PRIVACY_CONSENT=Y" \
  --network=host \
  -e DISPLAY -v $HOME/.Xauthority:/root/.Xauthority \
  -v /home/jintao/isaac_ws:/root/isaac_ws:rw \
  -v ~/docker/isaac-sim/cache/kit:/isaac-sim/kit/cache:rw \
  -v ~/docker/isaac-sim/cache/ov:/root/.cache/ov:rw \
  -v ~/docker/isaac-sim/cache/pip:/root/.cache/pip:rw \
  -v ~/docker/isaac-sim/cache/glcache:/root/.cache/nvidia/GLCache:rw \
  -v ~/docker/isaac-sim/cache/computecache:/root/.nv/ComputeCache:rw \
  -v ~/docker/isaac-sim/logs:/root/.nvidia-omniverse/logs:rw \
  -v ~/docker/isaac-sim/data:/root/.local/share/ov/data:rw \
  -v ~/docker/isaac-sim/documents:/root/Documents:rw \
  nvcr.io/nvidia/isaac-lab:2.3.0
```

第三步：克隆仓库并进入项目目录（容器内执行）。若已通过宿主机挂载工作区，跳过 git clone 直接进入目录即可。

```bash
cd /root/isaac_ws
git clone https://github.com/alannian/openarm_isaac_lab.git
cd openarm_isaac_lab
```

第四步：安装扩展包（容器内执行）。

```bash
python -m pip install -e source/openarm
```

第五步：验证任务注册。输出中应包含 Isaac-Lift-Tray-OpenArm-Bi-v0 和 Isaac-Lift-Tray-OpenArm-Bi-Play-v0。

```bash
python scripts/tools/list_envs.py
```

0.2 训练

以下命令均在容器内 /root/isaac_ws/openarm_isaac_lab 目录下执行。

冒烟测试（验证训练链路，约 1 分钟）：

```bash
python scripts/reinforcement_learning/rsl_rl/train.py \
  --task Isaac-Lift-Tray-OpenArm-Bi-v0 \
  --num_envs 64 --max_iterations 5 --headless
```

正式训练（推荐配置，显存不足时将 2048 改为 1024）：

```bash
python scripts/reinforcement_learning/rsl_rl/train.py \
  --task Isaac-Lift-Tray-OpenArm-Bi-v0 \
  --num_envs 2048 --max_iterations 10000 \
  --seed 42 --headless --logger tensorboard
```

训练日志和 checkpoint 保存在 logs/rsl_rl/openarm_bi_tray_lift/<run_id>/ 下，每 100 个 iteration 保存一次模型（model_100.pt、model_200.pt……）。

断点续训（指定已有 run 目录和 checkpoint 文件）：

```bash
python scripts/reinforcement_learning/rsl_rl/train.py \
  --task Isaac-Lift-Tray-OpenArm-Bi-v0 \
  --resume --load_run 2026-06-02_03-23-51 \
  --checkpoint model_200.pt --headless
```

0.3 回放

Play 环境自动将并行环境数降为 16 并关闭观测噪声，适合可视化。将 checkpoint 路径替换为实际文件路径。

```bash
python scripts/reinforcement_learning/rsl_rl/play.py \
  --task Isaac-Lift-Tray-OpenArm-Bi-Play-v0 \
  --num_envs 16 \
  --checkpoint logs/rsl_rl/openarm_bi_tray_lift/2026-06-02_03-23-51/model_200.pt
```

如需同时录制视频，在上述命令末尾追加 --video --video_length 300。回放结束后，TorchScript 和 ONNX 策略文件会自动导出到对应 run 目录的 exported/ 子目录。

0.4 查看训练曲线

在容器内（或宿主机上挂载相同路径后），执行：

```bash
python -m tensorboard.main --logdir=logs/rsl_rl/openarm_bi_tray_lift
```

浏览器打开 http://localhost:6006 即可查看所有 run 的奖励曲线。若容器内没有 tensorboard，先执行 pip install tensorboard 安装。也可以将 logs/ 目录下的 events.out.tfevents.* 文件复制到宿主机，在宿主机上启动 tensorboard 查看。

一、运行环境

1.1 操作系统与硬件
当前仓库和 README 均以 Linux 平台为主，推荐 Ubuntu 22.04。训练需要 NVIDIA GPU 和可用的 CUDA 驱动。若使用默认 4096 并行环境，建议显存较大；如果显存有限，可像当前仓库近一轮实验那样将环境数降到 2048。GUI 调试需要本地图形显示和 X11 转发权限，无头训练可直接使用 headless 模式。

1.2 软件版本
当前项目对应的软件栈为 Isaac Sim 5.1.0、Isaac Lab 2.3.0、Python 3.11。强化学习训练依赖 rsl-rl-lib 3.0.1 及以上版本，train.py 启动时会显式检查版本。扩展包 openarm 的 setup.py 中声明的额外 Python 依赖为 psutil，extension.toml 中声明的核心依赖包括 isaaclab、isaaclab_assets、isaaclab_mimic、isaaclab_rl 和 isaaclab_tasks。

1.3 实际部署方式
本项目实际使用 Docker 容器。README 中提供了 Isaac Lab 官方容器镜像的拉取命令，当前保留日志中的参数文件显示，实验是在容器内路径 /root/isaac_ws/openarm_isaac_lab 下完成的。因此，如果你希望完全复现当前项目的运行方式，建议把宿主机工作区 /home/jintao/isaac_ws 挂载到容器内的 /root/isaac_ws。

三、目录结构与模块功能

双臂托盘举升任务的核心代码位于 source/openarm/openarm/tasks/manager_based/openarm_manipulation/bimanual/lift 目录。lift_env_cfg.py 负责场景模板、观测、奖励、终止和课程的顶层配置；config/joint_pos_env_cfg.py 负责机器人、托盘、TCP 观测框架以及动作空间的具体实例化；config/__init__.py 负责 Gym 环境注册；config/agents/rsl_rl_ppo_cfg.py 保存 PPO 超参数；mdp/observations.py、mdp/rewards.py 和 mdp/terminations.py 分别实现自定义观测、奖励与终止逻辑。

训练与评估脚本位于 scripts/reinforcement_learning/rsl_rl。train.py 用于启动训练；play.py 用于加载 checkpoint 回放并导出策略。调试工具位于 scripts/debug，其中 inspect_bimanual_lift.py 用于在 GUI 中检查场景几何、TCP 坐标轴和抓握相关诊断量，solve_ready_pose.py 用于分析抓取点可达性。工具脚本位于 scripts/tools，其中 list_envs.py 用于验证任务注册，build_tray_usd.py 用于重新生成托盘 USD。

四、代码运行步骤

4.1 训练前几何检查
在正式训练前，建议先启动 GUI 并运行 inspect_bimanual_lift.py，确认左右 TCP、托盘抓取点、托盘姿态和初始抓握信号是否合理。命令如下。

cd /root/isaac_ws/openarm_isaac_lab
python scripts/debug/inspect_bimanual_lift.py --num_envs 1 --steps 3000

运行后，可以在 GUI 中看到左右末端 TCP 坐标轴，可从终端中看到托盘位置、托盘平整度、TCP 到抓取点距离、手指开合值、capture_band 等调试信息。初始状态下，capture_band 和 grasp_hold 应接近 0，而不是一开始就出现假抓握奖励。

4.2 冒烟训练
在确认几何正常后，可先做小规模冒烟测试验证训练链路。命令如下。

python scripts/reinforcement_learning/rsl_rl/train.py --task Isaac-Lift-Tray-OpenArm-Bi-v0 --num_envs 64 --max_iterations 5 --headless

如果该命令可以正常创建环境、启动 PPO 更新并在 logs/rsl_rl/openarm_bi_tray_lift 下生成日志目录，就说明训练链路已经打通。

4.3 正式训练
当前代码默认配置为 scene.num_envs 4096、num_steps_per_env 64、max_iterations 8000。若你的 GPU 显存足够，可以直接使用默认值。命令如下。

python scripts/reinforcement_learning/rsl_rl/train.py --task Isaac-Lift-Tray-OpenArm-Bi-v0 --headless

如果你希望采用当前仓库近一轮实验中已经实际跑通过的设置，可以显式覆盖环境数和迭代次数，例如使用 2048 并行环境和 10000 iterations。该设置已经在 2026-06-02_03-23-51 的 params 文件中留下记录。

python scripts/reinforcement_learning/rsl_rl/train.py --task Isaac-Lift-Tray-OpenArm-Bi-v0 --num_envs 2048 --max_iterations 10000 --seed 42 --headless --logger tensorboard

4.4 断点续训
若已有历史 checkpoint，可使用 resume 相关参数继续训练。命令格式如下。

python scripts/reinforcement_learning/rsl_rl/train.py --task Isaac-Lift-Tray-OpenArm-Bi-v0 --resume --load_run 2026-06-02_03-23-51 --checkpoint model_200.pt --headless

其中 load_run 对应 logs/rsl_rl/openarm_bi_tray_lift 下的 run 目录名，checkpoint 对应 run 目录中的模型文件名。

4.5 策略评估与回放
训练完成后，可使用 Play 变体环境加载模型进行回放。Play 环境会自动把并行环境数降到 16，并关闭观测噪声，更适合可视化。

python scripts/reinforcement_learning/rsl_rl/play.py --task Isaac-Lift-Tray-OpenArm-Bi-Play-v0 --num_envs 16 --checkpoint logs/rsl_rl/openarm_bi_tray_lift/2026-05-14_03-24-32/model_4999.pt

play.py 在加载模型后，还会在对应 run 目录下导出 TorchScript 和 ONNX 策略文件，导出目录为 exported。

4.6 视频录制与日志分析
如果需要录制训练或回放视频，可在 train.py 或 play.py 中增加 video 相关参数。例如，在回放时录制一段视频可以执行以下命令。

python scripts/reinforcement_learning/rsl_rl/play.py --task Isaac-Lift-Tray-OpenArm-Bi-Play-v0 --num_envs 16 --checkpoint logs/rsl_rl/openarm_bi_tray_lift/2026-05-14_03-24-32/model_4999.pt --video --video_length 300

python -m tensorboard.main --logdir=logs/rsl_rl/openarm_bi_tray_lift

若你的容器环境没有安装 tensorboard，可以先通过 pip 安装，或者将 event 文件导出到具备 tensorboard 的环境中查看。

4.7 重新生成托盘 USD
如果修改了托盘尺寸、质量或摩擦参数，可重新生成托盘 USD。执行脚本后，还需要同步检查 lift_env_cfg.py、rewards.py 和 observations.py 中的几何常量是否一致。

python scripts/tools/build_tray_usd.py

五、核心配置与参数说明

5.1 环境标识与顶层配置
训练环境 ID 为 Isaac-Lift-Tray-OpenArm-Bi-v0，评估环境 ID 为 Isaac-Lift-Tray-OpenArm-Bi-Play-v0。环境注册文件位于 bimanual/lift/config/__init__.py。顶层环境配置类为 BimanualTrayLiftEnvCfg，具体任务配置类为 OpenArmTrayLiftEnvCfg，评估配置类为 OpenArmTrayLiftEnvCfg_PLAY。

5.2 动作空间
动作总维度为 16。左臂和右臂各使用 7 维关节位置增量控制，scale 为 0.5。左右夹爪各使用 1 维二值动作，其中张开命令对应 0.044，闭合命令对应 0.0。这样的设计在保留连续关节控制能力的同时，降低了夹爪控制复杂度。

5.3 观测空间
观测维度约为 78。观测内容包括左右臂关节位置与速度、左右手指开度、左右 TCP 在机器人 root 系下的位置、TCP 指向各自抓取点的向量、托盘位置、姿态摘要、线速度、角速度、手部向下对齐标量、手部开合轴与托盘方向对齐标量以及左右臂上一步动作。训练模式下默认开启少量观测噪声，Play 模式关闭噪声。

5.4 几何常量
任务使用一组统一的几何常量。HALF_GRASP_Y 为 0.23 m，表示抓取点距托盘中心的绝对 y 距离。TRAY_BASE_HEIGHT 为 0.345 m，表示托盘静置时的质心高度。MINIMAL_LIFT_HEIGHT 为 0.385 m，用于判定托盘是否离开支架。TARGET_HEIGHT 为 0.495 m，对应举升目标高度。修改托盘尺寸时，必须同步更新这些常量与托盘 USD。

5.5 PPO 默认参数
当前代码默认使用 num_steps_per_env 64、max_iterations 8000、actor_hidden_dims 和 critic_hidden_dims 均为 256、256、128，init_noise_std 为 0.5，学习率 3.0e-4，gamma 0.99，lambda 0.95，entropy_coef 0.005。相比历史 run，当前版本更适合自然下垂初态和长时域训练。历史 4999 iteration run 中曾使用较浅网络、较大噪声和较软的 PD 参数，这是当前调优演化的重要参考。

5.6 四阶段课程
课程在策略步层面切换。15000 policy steps 后开启 grasp_hold 和 grasp_attempt；35000 policy steps 后开启带抓握门控的 lift_height、lifted 和 goal_height 奖励；55000 policy steps 后增加托盘水平、角速度惩罚、左右高度对称和平滑惩罚。按照 num_steps_per_env 等于 64 计算，这些阈值大约对应 234、547 和 859 个 PPO iterations。

六、核心函数说明

6.1 rewards.py
reach_handle 用于计算 TCP 到抓取点的 tanh 距离奖励。grasp_hold 计算双手真实抓握质量的均值，是抓握阶段的主力信号。grasp_attempt 在接近抓取点时鼓励夹爪尝试闭合，但权重较小，不参与举升门控。tray_lift_height、tray_is_lifted 和 tray_goal_height 用于描述举升进度和目标高度。_grasp_gate 是内部关键门控函数，只有当左右手都满足 near 与 capture_band 时，举升奖励才会真正生效。tray_flat、ee_height_symmetry 和 tray_ang_vel_penalty 则用于约束抬起后的平稳性。

6.2 observations.py
ee_position_in_robot_root_frame 返回 TCP 在机器人 root 系下的位置。ee_to_handle_vector_in_robot_root_frame 返回 TCP 指向抓取点的向量，是策略进行末端对位的关键几何信息。tray_position_in_robot_root_frame 和 tray_orientation_features 分别给出托盘位置和姿态摘要。hand_down_alignment 与 hand_span_alignment 用于描述手掌朝向和开合轴方向，为策略提供辅助姿态线索。

6.3 terminations.py
tray_dropped 用于检测托盘是否掉落到设定阈值以下。当前阈值为 0.22 m，明显低于托盘静置高度 0.345 m，避免轻微下沉就误触发终止。

6.4 inspect_bimanual_lift.py
该脚本用于训练前 sanity check。它会可视化左右 TCP frame，打印托盘长轴、托盘平整度、TCP 到抓取点距离、手指开合轴方向、手指与托盘 clearance 以及 capture_band 等信息，是排查几何错位和假抓握奖励的首选工具。

八、常见问题与解决办法

问题一：报错 No module named openarm。
原因通常是没有在容器内执行 python -m pip install -e source/openarm，或者执行安装后仍不在正确的容器环境中。解决方法是重新进入项目目录并安装扩展包。

问题二：list_envs.py 中看不到双臂托盘举升任务。
原因通常是 openarm.tasks 没有成功导入或者安装路径不正确。先确认 source/openarm 安装成功，再检查 bimanual/lift/config/__init__.py 是否存在且未被误改。

问题三：训练显存不足。
默认 4096 并行环境显存占用较大。如果出现 OOM，可将 num_envs 降到 2048 或 1024。当前仓库近一轮实验已经实际采用 2048 环境运行，这是最直接的参考配置。

问题四：GUI 无法启动或窗口黑屏。
通常与 DISPLAY、X11 权限或驱动有关。先在宿主机执行 xhost +，再检查 docker run 时是否正确挂载 .Xauthority 和 DISPLAY 环境变量。若只是训练，不必启动 GUI，直接使用 headless 模式即可。

问题五：策略学会推托盘或把托盘顶起来，而不是夹住再抬起。
这通常意味着奖励版本过旧，或者你修改了 rewards.py 后破坏了 _grasp_gate 逻辑。请检查当前 rewards.py 中 near、capture_band 和 _grasp_gate 的实现是否完整，并确认课程阶段没有被过早改动。

问题六：双臂明明接近托盘，但始终夹不住。
优先检查 TCP frame 是否仍然跟踪 openarm_left_ee_tcp 和 openarm_right_ee_tcp，而不是 hand 加固定 offset；其次检查 PD 参数是否仍为当前代码中的 stiffness 200 和 damping 24。若回退到较软参数，机械臂在托盘高度附近可能会明显下垂。

问题七：checkpoint 找不到。
train.py 会按 save_interval 保存模型。当前默认 save_interval 为 100，因此只有训练超过对应迭代数后才会看到 model_100.pt、model_200.pt 等文件。若目录中只有 model_0.pt，说明训练尚未进入下一次保存点或中途停止。

问题八：修改托盘尺寸后奖励和观测表现异常。
这通常说明 build_tray_usd.py、lift_env_cfg.py、rewards.py 和 observations.py 之间的几何常量没有同步。务必统一 HALF_GRASP_Y、TRAY_BASE_HEIGHT、TARGET_HEIGHT 等参数。

问题九：rsl-rl-lib 版本不正确。
train.py 启动时会检查 rsl-rl-lib 是否至少为 3.0.1。如果版本过低，脚本会直接给出提示。请在容器中安装或升级到兼容版本。
