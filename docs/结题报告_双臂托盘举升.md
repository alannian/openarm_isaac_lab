基于 Isaac Lab 的双臂 OpenArm 协同托盘举升强化学习项目结题报告

摘要
随着服务机器人、仓储搬运和协同制造的发展，双臂机器人对大尺寸、扁平类和需要稳定双手持握物体的操作需求日益增加。与单臂抓取立方体等标准任务相比，双臂协同托盘举升同时包含长距离到达、双侧对位、夹爪闭合、接触稳定、协同抬升和姿态保持等多个子问题，具有更强的接触耦合性和更高的控制难度。传统基于模型的控制方法在复杂接触、形封闭和多约束协同场景下建模成本较高，泛化到不同几何与初始状态时也存在明显局限，因此基于大规模并行仿真的强化学习方法具有较高研究价值。

本项目基于 NVIDIA Isaac Sim 5.1.0 与 Isaac Lab 2.3.0，围绕 OpenArm 双臂机器人构建了一个双臂协同托盘举升强化学习任务。项目使用 Manager-Based RL 环境架构，将场景、动作、观测、奖励、终止、随机化和课程机制模块化组织；采用 16 维动作空间和约 78 维几何增强观测空间；在奖励设计中引入“先夹住、再抬起”的四阶段课程与抓握门控机制，从而抑制通过推倒托盘、顶起托盘等非真实抓取行为骗取举升奖励的退化策略。当前代码版本使用更深的 PPO 网络、较保守的初始动作噪声、更高的关节 PD 刚度以及直接基于 USD 中 ee_tcp 链路的末端位姿观测，改善了自然下垂初态下的到达与抓取难题。

结合仓库中当前代码、训练脚本和日志产物，可以确认本项目已经形成了完整可运行的任务实现。代码侧已经完成 Isaac-Lift-Tray-OpenArm-Bi-v0 与 Isaac-Lift-Tray-OpenArm-Bi-Play-v0 两个环境注册，包含训练、回放、场景检查、抓取姿态分析和托盘 USD 重新生成等配套工具。实验侧在 logs/rsl_rl/openarm_bi_tray_lift 目录中保留了多轮长程训练记录，其中多次实验已经保存到 model_4999.pt，说明完整课程训练链路已经实际运行；2026-06-02 的最新 run 则显示当前代码版本正在按 10000 iterations 目标继续训练。项目的主要创新体现在双臂侧面骑夹扁平托盘任务建模、抓握门控反作弊奖励、自然下垂初态下的课程学习设计，以及面向 Docker 容器环境的可复现实验流程。

关键词
双臂协同操作，强化学习，Isaac Lab，托盘举升，Docker 仿真训练

一、引言

1.1 研究背景
双臂机器人在餐饮配送、物流分拣、板材搬运、实验室自动化和协同装配等场景中具有明显优势。相比单臂系统，双臂系统能够同时施加对称支撑力和约束力，更适合操作长条形、扁平板状或重心分布离散的大尺寸物体。托盘举升就是这类典型任务：目标物体既不是单点抓取即可稳定搬运的小型刚体，也不是简单轨迹跟踪就能完成的无接触操作，而是需要在两侧同步到位后形成可承载的接触状态，再在举升过程中保持姿态稳定。

在仿真学习层面，Isaac Lab 依托 Isaac Sim 的 GPU 并行物理仿真能力，适合构建多环境、大样本、高频交互的机器人强化学习任务。OpenArm 作为开源机械臂平台，在 Isaac Lab 中已经具备单臂到达、单臂举块、单臂开抽屉以及双臂到达等任务基础。相比这些已有任务，双臂托盘举升更强调两侧对位、形封闭抓取和受重力影响的稳定协同，是对现有开源任务集的一项具有代表性的扩展。

1.2 研究意义
本项目具有三方面意义。其一，在学术层面，项目探索了自然下垂初态、长时域到达、丰富接触以及奖励反作弊等问题的联合解决方法，对双臂协同操作任务的 MDP 设计具有参考价值。其二，在工程层面，项目形成了从场景建模、任务注册、训练、回放、日志分析到策略导出的完整闭环，可作为后续 sim-to-real、模仿学习或多任务迁移的实验基础。其三，在应用层面，托盘和板材搬运本身就是双臂机器人在服务和制造场景中的常见需求，项目构建的环境能够进一步扩展到托盘搬运、定点放置、动态避障和人机协同等更复杂任务。

1.3 国内外研究现状
国际上，机器人操作领域已经广泛使用强化学习解决到达、抓取、门柜开合和灵巧操作等任务。OpenAI、DeepMind 和 NVIDIA 相关工作表明，在高并行仿真环境下，端到端学习方法能够获得复杂接触任务所需的策略表示能力。Isaac Gym 和 Isaac Lab 生态中，Franka、UR 等机械臂的大量单臂任务已经成为标准 benchmark，但主要集中于 reach、cube lift、cabinet 等较规则的操作对象。双臂方面，现有工作更多关注双臂 reach、双臂抬杆、双手装配或遥操作数据采集，针对“侧面骑夹扁平托盘并稳定举升”这一具体场景的公开实现相对较少。

国内研究则更多集中于基于模型的双臂协调控制、视觉伺服抓取以及基于强化学习的操作技能综述与尝试。总体来看，双臂协同强化学习仍然面临两个难点：一是接触建模与奖励设计复杂，容易出现作弊策略；二是任务跨度长，从初始位姿到真正举升之间存在较大的探索鸿沟。本项目正是围绕这两个难点展开，通过更贴近物理约束的场景设计与更具阶段性的奖励构造，提升策略学习的稳定性与真实性。

1.4 研究目标
本项目的研究目标可以概括为五点。第一，在 Isaac Lab 中建立双臂 OpenArm、中央支架和自定义托盘组成的稳定物理场景。第二，设计与任务几何一致的动作空间、观测空间、奖励项、终止条件和随机化策略，使策略能够从自然下垂初态学习到“到达、夹持、举升、保持稳定”的完整技能链。第三，基于 RSL-RL 部署可复现的 PPO 训练流程，并支持 GUI 检查、无头训练、回放评估和策略导出。第四，针对托盘竖立骗分、空中闭合等常见失败模式，给出可落地的奖励门控与课程式优化方案。第五，形成配套文档和代码结构，保证任务可复现、可调试、可扩展。

1.5 主要研究内容
围绕上述目标，项目的主要研究内容包括四部分。第一部分是场景与资产建模，包括 OpenArm 双臂机器人、扁平板托盘、中央支架和末端 TCP 观测框架。第二部分是 MDP 设计，包括 16 维动作、约 78 维观测、四阶段奖励和终止判据。第三部分是训练与评估流程，包括基于 RSL-RL 的 PPO 训练脚本、日志保存、断点续训、Play 模式评估以及 TorchScript 和 ONNX 导出。第四部分是工程支撑工具，包括环境注册检查脚本、场景 sanity check 脚本、抓取就绪姿态求解工具和托盘 USD 生成脚本。

二、相关理论与技术基础

2.1 机器人运动控制原理
本项目采用关节位置增量控制方式。策略每个决策步输出左右机械臂各 7 维关节增量和左右夹爪各 1 维动作，总计 16 维。其中臂部动作通过 JointPositionActionCfg 作用于 14 个关节，scale 为 0.5，并在默认位姿偏置附近调整；夹爪使用 BinaryJointPositionActionCfg，将动作映射为张开 0.044 m 与闭合 0.0 m 两种目标位置。该设计兼顾了连续控制与抓握开合的离散性，既保留了 PPO 对连续动作学习的优势，又避免了把夹爪动作处理成高维复杂控制的问题。

在执行器层面，当前代码版本显式提高了 openarm_arm 执行器的刚度和阻尼，将 stiffness 从早期实验中的 80 提升到 200，将 damping 从 4 提升到 24。这样做的动机来自自然下垂初态下的重力补偿问题：若刚度不足，双臂在伸向托盘高度附近时会发生明显下垂，导致看似到位的动作无法在物理上托住或夹住托盘，进一步削弱奖励函数提供的学习信号。通过提高 PD 参数并直接使用 USD 中的 openarm_left_ee_tcp 与 openarm_right_ee_tcp 作为末端 frame，可显著提升观测、奖励和真实几何之间的一致性。

2.2 强化学习算法
训练算法采用 RSL-RL 提供的 PPO。当前代码中的 OpenArmTrayLiftPPORunnerCfg 使用 num_steps_per_env 为 64，默认 max_iterations 为 8000，actor 与 critic 网络均采用三层 MLP，隐藏层为 256、256、128，激活函数为 ELU，初始动作噪声标准差为 0.5，熵系数为 0.005，学习率为 3.0e-4，gamma 为 0.99，lambda 为 0.95，clip 参数为 0.2，desired_kl 为 0.016。该配置相比仓库中保留的 2026-05-14 长程训练配置有明显演化：后者仍使用 128、128、64 的网络、1.0 的初始噪声、0.0002 的学习率以及 gamma 0.995、lambda 0.97。由此可见，当前代码并非静态版本，而是在多轮训练基础上针对自然初态和长时域探索问题进行了持续优化。

2.3 仿真环境与框架基础
Isaac Lab 采用 Manager-Based RL 环境架构，将机器人学习任务拆分为场景、动作、观测、奖励、终止、随机化和课程等相互独立但可组合的模块。本项目的顶层环境类为 BimanualTrayLiftEnvCfg，继承自 ManagerBasedRLEnvCfg。场景模板在 lift_env_cfg.py 中定义，机器人、托盘和末端 frame 的具体实例化在 joint_pos_env_cfg.py 中完成；奖励、观测和终止分别由 mdp/rewards.py、mdp/observations.py 和 mdp/terminations.py 负责。整个框架的优点是能够较快地试验不同 MDP 方案，并通过配置类将任务逻辑从训练脚本中解耦。

与环境框架配套的实验运行方式统一为 Docker 容器。仓库 README 提供了 Isaac Lab 官方镜像 nvcr.io/nvidia/isaac-lab:2.3.0 的使用方式，而日志参数文件中记录的 USD 路径为 /root/isaac_ws/openarm_isaac_lab，说明当前保留实验是在 Docker 容器中挂载宿主机工作区后完成的。将部署方式统一到容器中，可以显著减少 Isaac Sim、CUDA、USD 与 Python 运行时之间的版本耦合问题，提高复现稳定性。

2.4 课程学习与奖励塑形
本项目的奖励设计核心是解决两个典型失败模式。第一种失败是举升奖励过硬门控导致随机策略几乎采不到正样本，最终只学会在托盘附近悬停而不闭合抓取。第二种失败是举升奖励完全不门控，导致策略通过推竖托盘、从下方顶起托盘等方式提高质心高度来骗取举升分。为此，项目采用四阶段课程。阶段一只保留 reach 奖励，使双臂从自然下垂姿态先学会接近抓取点。阶段二开启 grasp_hold 和 grasp_attempt，使策略学习真实夹持。阶段三再开启所有举升奖励，但这些举升奖励统一乘以 _grasp_gate，只在左右手都形成真实抓握时产生有效梯度。阶段四增加 tray_flat、ee_symmetry、tray_ang_vel 和动作平滑惩罚，使举升后的托盘更平稳。

所谓真实抓握由 near 与 capture_band 共同度量。near 衡量 TCP 是否到达该侧抓取点附近；capture_band 则利用扁平板被夹在双指之间时手指开度会稳定停留在板半厚附近这一物理事实，将真实夹持与“空中闭合”或“从下顶托”区分开。正是这个机制从根本上封堵了推倒托盘骗分路径，是本任务可以持续收敛到正确策略的关键。

三、项目实现过程

3.1 仿真环境搭建
项目场景由双臂 OpenArm、中央支架、扁平板托盘、地面和穹顶灯光构成。托盘由 scripts/tools/build_tray_usd.py 生成或重建，当前几何为 0.36 m 乘 0.50 m 乘 0.03 m，质量 0.5 kg，长轴沿托盘局部 Y 方向。中央支架尺寸为 0.12 m 乘 0.24 m 乘 0.33 m，支撑托盘中部，使托盘两端形成悬空区域，便于夹爪从侧面插入板边形成形封闭抓取。根据 lift_env_cfg.py 中的统一常量，托盘静置质心高度为 0.345 m，离台判定高度为 0.385 m，目标举升高度为 0.495 m，左右抓取点位于托盘局部坐标的 y 等于正负 0.23 m 处。

在机器人初态上，当前代码明确采用“完全自然下垂初态”。左右臂 14 个关节全部初始化为 0，夹爪张开至 0.044 m，不再预置弯肘或预抓取姿态。该设定更接近真实机器人上电后的初始状态，也使 reach 阶段真正成为策略需要学习的能力，而不是通过人工初始化绕过。为了验证这个初态与场景几何是否合理，项目提供了 scripts/debug/inspect_bimanual_lift.py 脚本，可在 GUI 中直接查看末端 TCP 坐标轴、托盘长轴、抓取点位置、手指与托盘 clearance 以及 capture_band 等关键诊断量。

3.2 强化学习框架部署过程
本项目全部实验使用 Docker 运行。典型流程是先拉取 nvcr.io/nvidia/isaac-lab:2.3.0 镜像，再通过 docker run 挂载宿主机工作区、Isaac Sim 缓存目录、X11 显示权限和日志目录。结合当前仓库中保留的 env.yaml，可知实际实验工作目录位于容器内的 /root/isaac_ws/openarm_isaac_lab。进入容器后，通过 python 或 python3 执行 python -m pip install -e source/openarm 完成扩展包安装，然后使用 scripts/tools/list_envs.py 验证 Isaac-Lift-Tray-OpenArm-Bi-v0 与 Isaac-Lift-Tray-OpenArm-Bi-Play-v0 已正确注册。

训练入口脚本为 scripts/reinforcement_learning/rsl_rl/train.py。该脚本先启动 Isaac Sim，再通过 hydra_task_config 装载任务配置与 PPO 配置，随后创建环境、封装视频录制、保存参数和 Git 状态并启动 OnPolicyRunner 训练。回放入口为 scripts/reinforcement_learning/rsl_rl/play.py。该脚本可从指定 checkpoint 加载策略，在 Play 环境中关闭观测噪声并导出 TorchScript 与 ONNX 策略文件。除此之外，项目还提供了 scripts/debug/solve_ready_pose.py 用于分析到达抓取点的关节可达性，便于在训练收敛困难时从 IK 角度排查问题。

3.3 核心算法设计与优化
这一部分是任务能否真正学会“到位、夹住、抬起、保持平稳”的核心。当前实现并不是简单地把双臂关节状态送入 PPO，而是围绕托盘侧面抓取这一几何过程，按“动作空间设计、观测空间设计、奖励函数设计、四阶段课程调度”四个层次构建学习问题。

3.3.1 动作空间设计
动作空间总维度为 16。左臂和右臂各使用 7 维关节位置增量动作，分别作用于 14 个臂部关节，控制方式为 JointPositionActionCfg，scale 设为 0.5，并结合默认关节偏置实现增量控制；左右夹爪各使用 1 维二值开合动作，通过 BinaryJointPositionActionCfg 在张开 0.044 m 与闭合 0.0 m 两种目标之间切换。这样的动作设计有两个直接好处：一是臂部仍然保持连续控制，适合 PPO 学习细致的到达与抬升行为；二是夹爪被压缩为低维开闭决策，避免将手指接触问题转化为不必要的高维连续控制。

3.3.2 观测空间设计
当前观测空间约为 78 维，且几乎全部围绕任务几何来组织。第一类是本体感知信息，包括左右臂 14 个关节的位置与速度，以及左右手指关节位置；训练模式下这些量叠加了小幅均匀噪声，其中关节位置与速度噪声范围约为负 0.01 到正 0.01，手指位置噪声范围约为负 0.005 到正 0.005，用于提升策略对测量扰动的鲁棒性。第二类是末端执行器与抓取目标之间的相对几何信息，包括左右 TCP 在机器人 root 坐标系下的位置，以及左右 TCP 分别指向各自抓取点的三维向量。这里的抓取点不是人工拍脑袋定义的固定偏移，而是由托盘局部坐标中的两端点通过托盘当前位姿实时变换得到，因此当托盘发生平移或偏航时，策略仍能直接感知“还差多少、应往哪走”。

第三类是托盘状态信息，包括托盘质心在 root 系下的位置、托盘姿态摘要、线速度和角速度。姿态摘要没有使用欧拉角，而是使用托盘局部 Z 轴在世界系中的投影以及托盘长轴在水平面的投影，分别刻画倾斜程度与偏航方向，从而避免欧拉角奇异性。第四类是手部姿态信息，包括 hand_down_alignment 和 hand_span_alignment 两个标量。前者反映手部局部轴与世界负 Z 方向的对齐程度，用于描述手掌是否朝下；后者反映夹爪开合轴与托盘参考方向之间的相对对齐，用于给策略提供“以什么姿态靠近板边”这一额外线索。第五类是历史动作信息，即左右臂上一步动作值，用于让策略感知控制变化趋势，帮助抑制抖动。需要强调的是，二值夹爪的 raw action 没有并入历史动作观测，这是代码中刻意做出的选择，因为该量对环境的物理梯度不稳定，强行送入观测反而会干扰学习。

这些观测项共同体现了一个设计原则：策略不只知道“自己关节转到了哪里”，更知道“末端距离抓取点还有多远、托盘现在是否倾斜、两只手是否等高、物体是否在摇晃”。因此当前观测空间实际上是面向任务几何和接触成败而构造的，而不是一般性的机器人状态堆叠。

3.3.3 奖励函数设计
奖励函数是本项目最关键的部分。当前实现将奖励划分为接近、抓握、举升、稳定和平滑五组。接近奖励由左右两侧各两项组成，即 left_reach_coarse、right_reach_coarse、left_reach_fine 和 right_reach_fine。它们底层都调用 reach_handle，通过 1 减 tanh 距离核对 TCP 与侧面抓取点之间的距离进行奖励塑形；其中 coarse 项使用较大的 std 0.15，在远距离阶段也能提供梯度，fine 项使用较小的 std 0.03，用于在接近抓取点时继续细化对位精度。

抓握奖励由 grasp_hold 和 grasp_attempt 组成。grasp_hold 是当前代码中真正表征“是否抓住”的主力奖励，它并不是简单检查夹爪是否闭合，而是把单手抓握质量定义为 near 与 capture_band 的乘积。near 反映 TCP 是否处在对应侧抓取点附近，形式为 1 除以 1 加距离归一化平方；capture_band 则利用托盘厚度为 0.03 m 这一几何事实，检测手指开度是否停留在板半厚附近。代码中夹爪全开约为 0.044，空中完全闭合约趋近 0，真正把托盘板夹在双指之间时，手指开度会稳定停留在约 0.015 附近，因此只有“靠近正确抓取点”且“板确实被夹在双指之间”时，抓握质量才会高。grasp_attempt 则是较弱的辅助项，它只在接近抓取点时鼓励夹爪尝试闭合，帮助策略更快发现真实抓握，但它本身不代表已经抓住，因此权重明显低于 grasp_hold，且不会参与后续的举升门控。

举升奖励包括 lift_height、lifted、goal_height_coarse 和 goal_height_fine 四项。lift_height 根据托盘质心高度从静置高度 TRAY_BASE_HEIGHT 到目标高度 TARGET_HEIGHT 的归一化进度给出密集奖励；lifted 用于奖励托盘越过 MINIMAL_LIFT_HEIGHT 这一离台阈值；goal_height_coarse 与 goal_height_fine 则继续使用 tanh 核，让托盘高度逐步逼近目标高度，其中 coarse 项的 std 为 0.10，fine 项的 std 为 0.03。最关键的是，这四项举升奖励全部乘以 _grasp_gate。_grasp_gate 不是一个宽松条件，而是左右手真实抓握质量的乘积，因此只有当两只手都在正确位置上形成真实夹持时，举升相关奖励才会真正生效。这样一来，策略通过推托盘、顶托盘、把托盘怼竖等方式即便偶然提高了物体质心高度，也无法获得有效举升收益。

稳定性奖励包括 tray_flat、ee_symmetry 和 tray_ang_vel_penalty。tray_flat 只在托盘离台后计分，它通过托盘局部 Z 轴与世界 Z 轴的对齐程度衡量托盘是否保持水平；ee_symmetry 通过两只 TCP 的高度差构造奖励，鼓励双臂等高协同，避免一高一低导致托盘倾斜；tray_ang_vel_penalty 在托盘抬起后惩罚角速度平方，抑制摇摆。平滑性奖励则包括 action_rate_l2_arm_only、left_joint_vel 和 right_joint_vel。action_rate_l2_arm_only 只惩罚左右臂动作在相邻控制步之间的变化量，而故意跳过二值夹爪动作；left_joint_vel 和 right_joint_vel 则对双臂关节速度平方施加惩罚，降低快速摆动和末端冲击。

3.3.4 四阶段课程机制
虽然上面所有奖励项都在配置中被定义出来，但它们并不是从训练第一步就以相同权重同时打开，而是通过课程机制按四个阶段逐步引入。第一阶段对应 0 到 15000 个 policy steps，大约是 0 到 234 个 PPO iterations。在这一阶段，抓握奖励和举升奖励的权重都保持为 0，策略的主导信号是左右 reach 奖励，同时保留较弱的等高与平滑正则项。这一阶段的核心目标不是抬起托盘，而是让双臂从完全自然下垂初态学会稳定伸向托盘两侧的抓取点。

第二阶段在 15000 个 policy steps 之后开启。此时课程通过 modify_reward_weight 将 grasp_hold 权重设置为 6.0，将 grasp_attempt 权重设置为 1.5。也就是说，策略开始被明确鼓励去形成真实抓握，其中 grasp_hold 是主信号，grasp_attempt 是辅助信号。这个阶段的设计重点是跨越“到达之后为什么要闭合夹爪、怎样闭合才算真抓住”这一探索鸿沟。

第三阶段在 35000 个 policy steps 之后开启。此时门控举升奖励被整体打开：lift_height 权重设为 8.0，lifted 权重设为 4.0，goal_height_coarse 权重设为 8.0，goal_height_fine 权重设为 4.0。由于这些项全部乘以 _grasp_gate，因此课程并不是简单地告诉策略“把托盘抬高就行”，而是明确规定“先双手真实夹住，再通过抬高托盘获取收益”。这一阶段是从抓住过渡到真正抬起的关键阶段，也是本任务用来抑制作弊策略的核心机制。

第四阶段在 55000 个 policy steps 之后开启，对稳定性和动作质量进行强化。此时 tray_flat 权重被提升到 5.0，tray_ang_vel_penalty 权重设为负 2 乘 10 的负三次方，ee_symmetry 权重从初始的 0.3 提升到 2.0，action_rate 惩罚从负 1 乘 10 的负四次方提升到负 5 乘 10 的负三次方，左右臂关节速度惩罚也从负 5 乘 10 的负四次方提升到负 1 乘 10 的负三次方。换言之，第四阶段优化的重点已经不再是“是否能抬起来”，而是“抬起来后能否保持托盘水平、双手同步、动作平滑、系统不摇晃”。这正对应了任务从完成基本功能到形成稳定可用策略的最后一步。

3.3.5 当前版本的优化演化
从代码与历史 run 的对照来看，项目优化经历了明显迭代。早期 5000 iteration 长程 run 使用更浅的网络、较大动作噪声和较软的 PD 参数；当前代码版本则采用更深的 MLP、更保守的探索噪声、更高的刚度阻尼以及基于 ee_tcp 的更精确末端观测。这说明项目并非一次性堆砌配置，而是在训练失败模式、抓握作弊路径和几何诊断结果的反复验证中，逐步收敛到当前这一套“几何增强观测、真实抓握门控、分阶段奖励开启、后期稳定性强化”的系统方案。

3.4 代码编写思路
项目代码遵循 Isaac Lab 官方任务结构，并保持“配置与逻辑分离、几何常量单点管理、调试工具独立于训练主路径”的思路。任务注册位于 source/openarm/openarm/tasks/manager_based/openarm_manipulation/bimanual/lift/config/__init__.py；环境顶层配置位于 lift_env_cfg.py；机器人、托盘和动作实例化位于 joint_pos_env_cfg.py；奖励、观测和终止分别在 mdp 子目录中实现；PPO 超参数位于 config/agents/rsl_rl_ppo_cfg.py。训练与评估脚本独立存放于 scripts/reinforcement_learning/rsl_rl 下，调试脚本与工具脚本则分别位于 scripts/debug 和 scripts/tools 中。命名上大量使用 XxxCfg、tray_lift_height、ee_to_handle_vector_in_robot_root_frame 之类的语义化名称；注释则主要用于解释设计动机和物理含义，而不是重复代码字面意思，整体上满足结题报告对命名规范和注释清晰的要求。

3.5 实验方案设计
本项目实际采用的训练方案为 2048 个并行环境、5000 个 PPO iterations，训练硬件为 NVIDIA RTX 3060，单次完整训练时长约为 10 小时。训练过程中 num_steps_per_env 设为 64，episode 长度为 10 秒，物理仿真频率为 100 Hz，策略控制频率为 50 Hz，这样的设置在显存和训练效率之间取得了较为合适的平衡。结合课程切换阈值计算，15000、35000 和 55000 个 policy steps 大致对应 234、547 和 859 个 PPO iterations，因此 5000 iterations 的训练长度已经足以完整覆盖四阶段课程，使策略依次经历到达、抓握、举升和稳定性优化四个阶段。

4.4 终止情况、损失曲线与结果结论
从 Episode_Termination 曲线看，time_out 的末段 smoothed 值约为 0.978，而 tray_dropped 的末段 smoothed 值约为 0.0218。也就是说，训练后期绝大多数 episode 已经不再以托盘掉落的方式提前失败，而是运行到时间上限后正常结束。这里需要结合环境终止逻辑来理解：当前任务并没有设计“托盘成功举起后立即 success terminate”的终止项，因此较高的 time_out 占比并不意味着策略没有完成任务，反而更可能说明策略已经能够在较长时间内维持接触、夹持和举升状态，直到 episode 到达时限结束。结合 grasp_hold、lift_height 和 tray_flat 的同步提升，可以判断该次训练后期已经具备较稳定的抓取与举升能力，托盘掉落风险相较训练早期显著降低。

从 Loss 组曲线看，learning_rate 随训练推进逐步下降到约 2e-4，符合 PPO 自适应学习率调节的典型特征；surrogate loss 在中后期总体保持可控，没有出现持续发散；value_function loss 在前期上升后整体回落，说明 critic 在任务信号逐渐复杂化之后重新建立了较合理的值函数估计。需要指出的是，value_function 曲线末端存在一次明显尖峰，TensorBoard 面板甚至给出了 Infinity 显示。这更像是末段某个 batch 的值函数更新异常或日志读数异常，而不像整体训练已经崩溃，因为在同一阶段，mean_reward、grasp_hold、lift_height 和 tray_flat 并没有同步恶化，终止曲线也没有出现系统性退化。因此，该次训练的主要结论仍然成立，但若后续继续训练，仍应重点关注 critic 数值稳定性，并结合回放视频进一步核对末段 checkpoint 的真实行为质量。

综合本次 2026-06-01_12-35-30 训练的所有曲线，可以得到三个结论。第一，策略已经稳定越过 reach 和 grasp 两个前期阶段，真实抓握奖励显著建立。第二，举升相关奖励与托盘平稳性奖励在后期持续增长，说明策略已经学会将托盘夹离支撑并在一定程度上保持平衡。第三，当前结果更接近“已经具备可用性，但仍有继续优化空间”的阶段，即主要任务链路已经打通，但最终成功率统计、后期稳定性上限以及 value loss 数值健康性仍值得在后续实验中继续完善。

五、创新点总结

本项目的创新可以概括为五点。第一，在任务与场景层面，项目没有沿用标准的单臂抓块场景，而是基于 OpenArm 双臂构建了中央支架支撑、两端悬空、侧面骑夹的扁平托盘举升任务，使任务更贴近真实双臂协作搬运需求。第二，在奖励设计层面，项目提出并实现了基于 near 与 capture_band 的抓握质量度量，以及以双手抓握乘积构成的 _grasp_gate，将“必须真实夹住托盘才能拿到举升奖励”写入学习目标，从根本上抑制了推托盘竖立骗分和空中闭合等作弊策略。第三，在初态与控制层面，项目采用完全自然下垂初态，同时通过提高 PD 刚度和阻尼解决重力下垂导致的 reach 与 grasp 可学性问题，这比预先摆出人工抓取姿态更具研究真实性。第四，在几何一致性层面，项目直接使用 USD 中 ee_tcp 链路作为末端观测与奖励基准，并让 lift_env_cfg.py、observations.py、rewards.py 和 tray.usda 共享同一组几何常量，减少了观测、奖励和资产之间的隐性偏差。第五，在工程复现层面，项目提供了 Docker 化运行路径、训练与回放脚本、场景检查脚本、IK 探针和托盘 USD 构建工具，使任务不仅能训练，还能被系统地调试、分析和扩展。

六、问题与展望

尽管项目已经取得较完整的阶段性成果，但仍存在若干不足。首先，当前成果主要停留在仿真中，尚未完成真实 OpenArm 硬件上的部署验证，因此 sim-to-real 偏差仍是后续必须面对的问题。其次，仓库中虽然保留了多轮长程训练日志和模型，但尚未形成统一的成功率统计表、评估脚本输出摘要和论文版图表，导致结果展示的完整性弱于代码实现本身。再次，当前训练依然依赖较高的并行环境规模和 GPU 资源，若要面向更广泛的复现环境，还需要继续优化样本效率与显存占用。最后，项目文档早期存在多种部署表述，而当前实际实验流程完全基于 Docker，这次整理后虽已统一，但后续仍需保持文档与代码、日志之间的同步更新。

未来工作可沿五个方向推进。其一，补充批量评估脚本，对不同 checkpoint 的举升成功率、托盘姿态稳定性和持握时长进行统一统计。其二，在现有环境上引入更强的域随机化，例如托盘质量、摩擦系数、支架高度和传感器噪声扰动，提高策略鲁棒性。其三，将 solve_ready_pose.py 生成的可行姿态或遥操作轨迹引入模仿学习或行为克隆预训练，以缩短 reach 与 grasp 阶段的探索时间。其四，完成策略导出后的真实机器人控制接口适配，开展 sim-to-real 验证。其五，围绕托盘任务继续拓展搬运、放置、避障和多目标协同操作，形成更完整的双臂任务族。
